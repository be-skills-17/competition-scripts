# CLAUDE.md

Bash tooling that sets up a web development competition environment on one server with Docker: Traefik, Gitea
(git, container registry, Actions runners), MySQL + phpMyAdmin, Verdaccio, WUD, one container per competitor and
module, and organizer-provided PHP APIs. User docs: `README.md` (table of contents) and `docs/`.

## Golden rules

- **`competition.sh` is generated by [bashly](https://bashly.dev) from `src/`. Never edit it.** Edit `src/`, then:
  `docker run --rm --user $(id -u):$(id -g) -v "$PWD:/app" dannyben/bashly:2.0.0 generate`
  (no Ruby on the machine). Commit `src/` and the regenerated `competition.sh` together.
- **Run `tests/run.sh` after every change.** It checks that `competition.sh` matches `src/`, runs shellcheck and
  the bats tests (Docker only). Add/adjust bats tests in `tests/*.bats` for any logic that does not need Docker.
- Every command requires root (`filter_root`). Claude cannot `sudo` here (password), see "Testing" below.
- Move files with `git mv` (keeps history readable for the user, who reviews diffs closely).

## Layout

```
competition.sh            generated, do not edit
bashly-settings.yml       source_dir src, env production
src/bashly.yml            commands, args, flags, filters, dependencies, help texts
src/initialize.sh         runs before arg parsing (even --help): BASE_DIR, load_env_file, loads services/*/service.sh
src/before.sh             runs after parsing and filters: global --verbose (must be placed BEFORE the command)
src/<cmd>_command.sh      one per command (dashes -> underscores: import_frameworks_command.sh)
src/lib/*.sh              shared functions, bundled into competition.sh by bashly
services/<NN>-<name>/     compose.yaml + optional service.sh hooks, loaded at RUNTIME (not bundled)
config/main.json          competition config (validated by check-config / filter_valid_config)
config/apis/<dir>/        organizer PHP APIs, gitignored except config/apis/template/ (disabled)
data/                     persistent data (bind mounts), root/container-owned; dynamic/ = generated files
tests/                    run.sh, *.bats, test_helper.bash, fixtures/main.json, Dockerfile (bats + jq + GNU tar)
```

## How it works

- **Services**: `src/lib/services.sh` lists `services/[0-9]*-*/` in NN order (stop/clean reverse). Hooks are plain
  functions `service_<name>_<hook>` (dashes -> underscores) called through `run_service_hook` with a *computed*
  name, so grepping a hook name finds no caller. Hooks: `compose_file`, `pre_init`, `wait_ready`, `post_init`,
  `clean`. `init` = for each service: pre_init, `up -d`, wait_ready, post_init (gitea's post_init creates the
  runner token, the API token and the registry login used by later services). Services whose compose file is
  generated (`competitors`, `apis`) return it from `compose_file`; `apis` writes none when no API is enabled.
- **Config / .env**: `init` computes values from `main.json` and saves them to `.env` (domain, credentials,
  GITEA_TOKEN, REGISTRATION_TOKEN...). Paths are never saved: `set_paths` derives them from the script location;
  `load_env_file` re-applies them after sourcing because old `.env`/backups still contain paths.
- **Validation**: `validate_configuration` (`src/lib/config.sh`, jq) + `validate_apis` (`src/lib/apis.sh`). Names
  (usernames, subdomains, modules, API names) are `^[a-z0-9][a-z0-9-]*$` (DNS, image paths); passwords reject
  quotes, backslashes and control chars (inserted raw into SQL/JSON, read back via `@tsv`).
- **APIs**: one `php:<v>-apache` container per enabled API and competitor (`<username>_<name>`), code mounted
  read-only, per-competitor SQLite copy in `data/apis/<name>/<username>/` (owned by uid 33), entry point
  `services/75-apis/start-apache.sh` (document root + FallbackResource), CORS via Traefik middleware labels.
- **npm**: `init` (verdaccio post_init) and `import-frameworks` run `npm install` on every template's
  package.json + lockfile (fetched from Gitea) through Verdaccio for each platform, then cut npmjs off (default
  state). No npm list in main.json on purpose: the templates are the source. `npm-proxy on|off` toggles it; on
  failure the proxy is left on.
- **Backups**: `tar --numeric-owner` of data/, config/, dynamic/docker, .env, lock; backups/ is 700, archives 600.
  `backup` stops the stack for a consistent MySQL copy; `clean` backs up after `down -v`; `restore` = check,
  clean (which backs up), extract, `up` each service + wait_ready.

## Pitfalls (each one already bit us)

- Code at the top level of `src/lib/*.sh` runs BEFORE `initialize` (paths are empty): only functions and
  constants there.
- All services share the compose project `competition_scripts`: never use `--remove-orphans` (it would delete the
  other services). Stale API containers are found by the `competition.api` label instead.
- `docker compose` inside a `while read` loop eats stdin: read the list from fd 3 or redirect compose from
  `/dev/null`.
- `run_with_spinner` must exec `"$@"`, not `"$*"` (a blanket `$@`->`$*` shellcheck fix broke it once). In
  non-verbose mode the command output is hidden unless it fails.
- Files are root/container-owned (`data/`, `.env`, `dynamic/`): reading them as the user may fail; never chown the
  project.
- Editing tools strip trailing whitespace; some sources have it, so exact-match replacements can fail.
- Heredocs in shell commands: a Python/shell payload containing a line `EOF` ends a `<<'EOF'` heredoc early; use
  another delimiter (`PYEOF`, `SHEOF`).
- In `bashly.yml`, several entries share names (`backup` is a command AND restore's argument): anchor edits on
  unique context.
- Verdaccio 6 queries every declared uplink even for packages without `proxy:`: offline mode must remove the
  `uplinks:` section (see services/50-verdaccio/service.sh). `config/verdaccio/config.yaml` is generated from
  `config.template.yaml`.
- npm silently skips optional dependencies it cannot fetch (platform binaries): an install that succeeds
  proves nothing, compare the installed package lists instead (prefetch-npm does).
- `mysql:8.4.6` is pinned on purpose (data directory version); all images are pinned, bump tags deliberately.

## Testing without sudo

- Pure logic: bats (`tests/run.sh`, or `tests/run.sh tests/apis.bats`). Prove new tests can fail (temporarily
  reintroduce the bug, then restore).
- Commands on the real running stack: a throwaway copy without the root filter, deleted right after:
  `sed 's/\[ "\$EUID" -eq 0 \] || echo "This command must be run as root/true || echo "x/' competition.sh > .t.sh`
  Only for safe commands (help, check-config, recreate phpmyadmin, start). Never `clean`, `restore`, `init` on the
  user's stack without asking; tell the user which sudo commands remain to be run by them.
- Real URLs: `curl -k https://<host>.$DOMAIN --resolve <host>.$DOMAIN:443:127.0.0.1` (values from `.env`).

## Working with the user

- The user writes in French; answer in French. Code, comments, docs and commit messages are in English.
- For lists of improvements, do **one item at a time** and stop for review between items.
- Do not commit; the user commits after reviewing. Do not stage unless asked.
- Before coding a feature, explain the design and ask the open questions; the user answers precisely.
